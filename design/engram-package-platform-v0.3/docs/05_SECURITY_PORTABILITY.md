# Security, supply chain, portability and resource design

## 1. Threat and trust model

Trust first-party reviewed releases and local owner/OS permissions, not arbitrary remote package code. Attacker can submit archive, descriptor, malformed response, symlink/reparse, stale journal, copied approval, hostile source content, fake process PID, malicious workspace files and mismatched artifacts. A same-privilege local adversary may rewrite installation and metadata; checksums/CRC are integrity against corruption, not absolute security. Never represent this as an OS sandbox. Effective containment for untrusted code requires distinct OS isolation and independent authorization; deferred. Third-party upstream media/AI components must have pinned artifact, license, dependency/SBOM and footprint proof. Install trust does not grant model/spend/publish/ingest consent. No credentials in catalog, manifest, registry, journal, default export, support report or generated content; use OS credential vault or package-local protected vendor store only after user login; do not move secrets by default.

## 2. Path and archive admission

Use system-relative normalized path with strict component validation; reject `..`, `.`, empty, absolute drive/UNC/device paths, alternate data streams/colon, backslash, trailing dot/space, reserved DOS names incl device aliases, NUL/control chars, casefold collisions and Windows-equivalent normalized path aliases. Validate after path encoding/decoding and before effect, physical root resolved by existing root helper. Walk components without following links or reparse; reject symbolic links, junctions, reparse, hardlink or unsafe archive entries (no hardlink extraction), unsupported devices. Validate existing tree and destination containment; recheck immediately before write/delete using safe OS handles where feasible, no guarantee against hostile same-user TOCTOU without real isolation. Validate file-vs-dir conflicts, duplicate normalized member names, unexpected extra files, size and decompression ratio/count, max expanded bytes and available disk with rollback/scratch reserve. Do not write any unapproved target before full inventory admission. Stage isolated unique owner directory, safe extraction with bounded actual counts, verify every hash before launch, no execute-from-user workspace, no ambient PATH/CWD executable resolution. Quarantine untrusted bytes safely, never auto-delete unowned original.

Manifest trust bootstrap: reviewed pinned key IDs and approved publisher/repo identity stored outside artifact, detached signature of canonical manifest, per-archive and per-member digest, trusted metadata source; private signing key never distributed. Key rotation/revocation and offline freshness must be specified and tested before production; unknown/expired trust blocks new activation, can preserve installed usable offline version with warning under explicit approved policy. Offline import only exact approved manifest/artifact; self-calculated hash or HTTPS alone not equivalent to signature. Verify redistribution rights of Python/FFmpeg (build/config/codecs and notices/source obligations), Node/browser, TTS/weights/voice/fonts/stock assets. If redistribution not authorized, separate approved user fetch or disable feature. Do not include real model blobs in base release. Never auto-run unpinned upstream updater or install script.

## 3. Core release allowlist and upgrade

Current collector walks `_sys` recursively and relies on exclusion patterns. Replace extension-related traversal with positive static allowlist at boundary (do not rewrite unrelated legacy package semantics without proof). Exclude catalog-declared slot roots (`AI`, `ContentFlow`, `packages/*`) *before* recursive walk; exclude all user/cache/installed generation/venv/registry/model/data trees; ship reviewed descriptor/schema/wrapper source only, with exact expected staged manifest. If AI static helper source ever needs inclusion, explicitly enumerate exact reviewed files in separate release artifact rather than allow whole subtree. Case-insensitive checks, `system_dir` rename, hidden files, foreign nested sentinels. CI fixtures create fake credentials, model blobs, DB/WAL/SHM, workspaces, caches, app generation, config, runtime, logs, backups, unknown package; archive inspect must prove every forbidden byte/name absent and allowlist membership exact, not a pattern-only assertion. Maintain .gitignore for private trees, but release gate does not rely on .gitignore. Core updater stages only allowed core members and never overlays pack slot. Verify old version -> candidate and old helper behavior with fake state before actual distribution. Do not report old raw executable safe.

## 4. Execution modes and host footprint

Windows x64, standard user, local NTFS as P0; target actual supported Windows builds must match Engram baseline. Optional portable SSD as transfer media; network/sync/cloud directories/unsupported removable FS not certified for active SQLite/PG. Unicode/space paths tested; unsupported CMD characters diagnosed; no global PATH, registry alias, SUBST/junction, admin Windows service, driver install or automatic scheduled startup for packs. Existing Engram opt-in context menu remains existing behavior. GPU driver and mandatory OS dependency are prerequisites; no host installation without user approval. No Docker/WSL required for P0. Record host OS/arch, CPU flags, runtime binary ABI, disk and permissions, GPU driver/model/device capabilities, actual NVENC encode/decode separately from reported availability. Default `doctor` shallow metadata/physical state only; actual local encode or native provider load explicit `--deep` probe with isolated scratch and bounded resources. RTX 3060 VRAM cannot be assumed until target proof. CPU fallback explicitly configured, no silent quality degradation. ContentFlow local UI bind loopback only, token/origin/CSRF protections for writes, no unsolicited remote access, upload path containment and bounded size; close owned server on app exit. No server auth inheritance from pack manager.

Mode `OFFLINE_STRICT` requires effective egress control and actual network observation; no-network app config alone is not enforcement. P0 test CPU media fixture in disconnected Windows or supported isolation; if OS restriction unavailable mark strict assurance NOT_RUN/BLOCKED, do not claim no egress. Separate explicit network policy for metadata and artifact fetch. Local endpoint calls only approved loopback; no transparent cloud fallback. Business action approvals bind content digest/project/account/provider/limits, independent of install approval. Paid external AI and public posting are disabled by default; copied/restored jobs and stale approvals cannot invoke provider. Actual provider unknown outcome -> reconcile, no auto replay.

## 5. Shared resource lease P1

Initial scope: cooperating managed processes in one installation/session. Key GPU device identity, lease owner pack/generation/job, process PID+creation time, host/session identity, monotonic fence, heartbeat/expiry and observed device occupancy. Exclusive admission; atomic acquire with gate and resource state, recheck before work, release only matching token, crash recovery proves process exit/identity and device idle or remains blocked. Timeout alone does not prove process gone; PID reuse cannot revoke current owner. Do not kill unowned GPU process; if unknown occupancy, queue/defer. Use package-specific bounded work/drain; no default persistent supervisor. Foreground user work prioritized with bounded wait; no preemption by kill. New inference calls and CF render honor same lease; inherited child proc state checked. Cross-installation same GPU: per-root lease is insufficient. Before enabling concurrent roots, prove host/session namespace ACL, exclusive atomic primitive, stale owner recovery and device identity across roots; otherwise explicitly disallow co-managed concurrency, show scope limitation. Multiple OS users/unmanaged external tasks not controllable by this primitive. External worker/cloud optional CF feature requires separate trust, no provider credentials or shared live DB. Shared immutable model blob only if trust/license/digest/format and vendor API permit; do not dedup mutable stores or unsafe hardlinks. P1 actual workstation tests for LLM vs image/TTS/NVENC, OOM, cancel, driver unavailable and recovery; timing/VRAM evidence required.
